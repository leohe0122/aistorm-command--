# 定时任务

Command 有两个定时任务。它们只是两个受 `CRON_SECRET` 保护的 HTTP 接口，由服务器上的 crontab（或任何调度器，如 systemd timer、Kubernetes CronJob、云厂商定时触发器）按时调用。服务本身不内置调度，也不依赖任何托管平台。

| 任务 | 接口 | 建议时间 | 做什么 | 开关（系统设置） |
|---|---|---|---|---|
| 每日战情简报 | `POST /api/scheduled/daily-briefing` | 每天 08:30（新加坡时间）= 00:30 UTC | 汇总客户数据，用 AI 生成简报，推送到飞书群 | 飞书推送 → Webhook 地址与“启用每日推送” |
| 拜访纪要提醒 | `POST /api/scheduled/visit-reminder` | 每天 09:00（新加坡时间）= 01:00 UTC | 找出 24–72 小时前有拜访但没有纪要的客户，推送提醒 | `feishu_visit_reminder_enabled=true`（复用简报的飞书 Webhook） |

没有配置飞书 Webhook 或开关关闭时，接口返回 `{"ok":true,"skipped":...}`，不做任何事。每日简报会调用一次 AI 模型，费用记在本部署“AI 模型配置”的 Key 上。

## 1. 设置 CRON_SECRET

在服务的环境变量里设置一个足够长的随机值（不要复用其他密钥）：

```bash
openssl rand -hex 32
```

- 未设置 `CRON_SECRET` 时，两个接口一律返回 `503`，不会被公开触发。
- 调用时用任一请求头携带：`Authorization: Bearer <CRON_SECRET>` 或 `X-Cron-Secret: <CRON_SECRET>`。
- 凭证错误返回 `401`。

## 2. 在服务器上配置 crontab

把密钥放在只有运行用户可读的文件里，避免出现在 `crontab -l` 和进程列表中：

```bash
sudo install -m 600 -o command -g command /dev/null /etc/command/cron.env
echo 'CRON_SECRET=<与服务相同的值>' | sudo tee /etc/command/cron.env >/dev/null
```

`crontab -e`（以运行服务的用户，如 `command`）：

```cron
# 时间为服务器时区；下例假设服务器为 UTC
30 0 * * * . /etc/command/cron.env && curl -fsS -m 300 -X POST -H "Authorization: Bearer $CRON_SECRET" http://127.0.0.1:3000/api/scheduled/daily-briefing >> /var/log/command-cron.log 2>&1
0  1 * * * . /etc/command/cron.env && curl -fsS -m 300 -X POST -H "Authorization: Bearer $CRON_SECRET" http://127.0.0.1:3000/api/scheduled/visit-reminder >> /var/log/command-cron.log 2>&1
```

- 直接调用本机端口（`127.0.0.1:3000`，与 `PORT` 一致），不经过公网与反向代理。
- 服务器时区若为 `Asia/Singapore`，把时间改为 `30 8` 和 `0 9`。使用 cronie 的系统也可以在 crontab 顶部写 `CRON_TZ=Asia/Singapore`。
- 多实例部署时只在一台机器上配置，否则会重复推送。

## 3. 手动验证

```bash
. /etc/command/cron.env
curl -i -X POST -H "Authorization: Bearer $CRON_SECRET" http://127.0.0.1:3000/api/scheduled/visit-reminder
# 未开启提醒时应返回 200 与 {"ok":true,"skipped":"visit reminder disabled"}
curl -i -X POST http://127.0.0.1:3000/api/scheduled/visit-reminder
# 不带凭证应返回 401
```

## 与 Manus 时期的区别

Manus 时期由平台的 Heartbeat 服务按 `manus-heartbeat create` 创建的任务回调，并用平台签发的 cron JWT 鉴权。迁出后这两部分都已删除，鉴权只看 `CRON_SECRET`。
