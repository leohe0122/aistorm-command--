# 数据库迁移说明

## 背景

生产库早期由 `scripts/apply-migrations.mjs` 逐条执行 SQL 建表，没有 drizzle 的迁移登记表 `__drizzle_migrations`。
因此直接运行 `pnpm db:push`（即 `drizzle-kit generate && drizzle-kit migrate`）会从 0000 号迁移开始，试图重建已存在的 `users` 等表而失败。

不要再用 `apply-migrations.mjs` 重放全部迁移：其中包含早期的 `ALTER TABLE … MODIFY COLUMN`，重放会把字段临时改回旧定义，可能截断或拒绝现有数据。

## 一次性建立基线（每个数据库只做一次）

```bash
# 1. 只检查：核对数据库已包含 0044 号迁移时的全部表和字段
pnpm db:baseline --baseline 0044_fast_shinko_yamashiro

# 2. 检查通过后登记基线
pnpm db:baseline --baseline 0044_fast_shinko_yamashiro --apply

# 3. 执行基线之后的新迁移（目前为 0045：新建 evidence、assessments、ai_runs）
pnpm drizzle-kit migrate
```

脚本发现缺少表或字段时会停止，不写入任何内容。

## 之后的日常流程

- 改 `drizzle/schema.ts` 后，GitHub Actions 会在功能分支上自动生成迁移文件并提交。
- 发布时运行 `pnpm db:push`（或 `pnpm drizzle-kit migrate`），只会执行尚未登记的新迁移。
